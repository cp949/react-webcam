# @cp949/react-webcam 2.0.0 배포 준비

## 인증 실패 후 2.0.0 배포 재시도

`chore: release v2.0.0` 커밋과 `v2.0.0` 태그, 원격 push는 끝났고 npm 인증에서
`ERR_PNPM_OTP_NON_INTERACTIVE`가 발생했다. npm 조회 시 `latest`는 아직 1.3.0이다.
버전 증가·커밋·태그를 반복하지 않고, 사용자의 대화형 터미널에서 다음 명령만 실행한다.

```bash
pnpm --filter @cp949/react-webcam publish --no-git-checks
npm view @cp949/react-webcam version dist-tags --json
```

인증 프롬프트에서 OTP 또는 브라우저 인증을 완료한다. OTP나 인증 토큰을 커밋하지 않는다.
위험: 높음. 첫 명령은 현재 2.0.0 패키지를 npm에 공개한다.
rollback: 같은 버전을 덮어쓸 수 없다. 문제가 있으면 소비자 버전을 1.3.0으로 고정하고 수정 버전을 배포한다.

다음 릴리스부터는 문자열 배포 훅 대신 release-it 내장 npm 플러그인이 pnpm을
대화형으로 실행한다. 사람이 인증할 때는 `pnpm release-it`에 `--ci`를 붙이지 않는다.

## 최초 배포 준비 기록

- 준비일: 2026-10-18.
- 배포 대상: `@cp949/react-webcam` 2.0.0.
- npm `latest`: 1.3.0. 2.0.0은 아직 배포하지 않았다.
- 소스의 `package.json` 버전은 1.3.0으로 유지한다. `release-it`이 배포할 때 2.0.0으로 올린다.
- `feat!` 커밋의 `BREAKING CHANGE` 푸터와 Conventional Commits 설정으로 major 증가를 확인했다.
- 수기 변경 내역은 이 문서에 보관한다. `CHANGELOG.md`는 릴리스 도구가 생성한다. 수기 `Unreleased` 절을 남기지 않아 같은 변경이 중복 기록되지 않게 한다.

## 변경 내역

### 호환성 변경

- `SecurityError`: `insecure-context` / `insecure`에서 `security-error` / `error`로 변경한다. 문서의 미디어 사용 제한을 처리하는 소비자는 분기를 수정한다. 실제 보안 컨텍스트 문제는 계속 `insecure-context` / `insecure`로 보고한다.
- `WebcamErrorCode`에 `security-error`, `policy-blocked`를 추가한다. 모든 값을 나열하는 switch나 안내 문장 맵을 갱신한다.
- 확인된 정책 차단은 `policy-blocked` / `denied`로 보고한다. 원인이 확인되지 않은 `NotAllowedError`는 `permission-denied` / `denied`를 유지한다.

### 추가 기능

- 기존 video에 연결하는 `useWebcam`, `UseWebcamOptions`, `UseWebcamResult`를 공개한다.
- `isFrameReady`, 카메라 재시도, 영상 재생 제어를 제공한다.

### 수정

- HTTP에서 미디어 API가 없어도 보안 컨텍스트 문제를 먼저 안내한다.
- 호출자가 소유한 `srcObject`를 보존하고 훅이 연결한 스트림만 분리한다.
- 정책 검사 API가 예외를 던지면 브라우저의 `getUserMedia` 판단에 맡긴다.
- 스트림 교체 시 이전 해상도를 버리고 새 메타데이터를 기다린다.

## 최초 배포 준비 시 실행 순서

저장소 루트의 `main` 또는 `dev` 브랜치에서 실행한다. `dev`에서도 정식 npm 버전과
`v2.0.0` 태그를 배포한다. prerelease로 자동 전환하지 않는다.
현재 브랜치에 배포할 변경사항이 모두 커밋되어 있고 원격 변경사항이 반영되어 있는지 확인한다.

```bash
git fetch origin
git branch --show-current
git status --short
pnpm test
pnpm check-types
pnpm lint
pnpm --filter chrome75-react-consumer test:packed
pnpm release-it --dry-run --ci
```

`git branch --show-current`가 `main` 또는 `dev`이고 `git status --short`가 비어 있어야 한다.
dry-run에 `1.3.0...2.0.0`과 `BREAKING CHANGES`가 나오는지 확인한다.
`package.json` 버전을 먼저 올리거나 `v2.0.0` 태그를 미리 만들지 않는다.

실제 배포는 npm 인증이 된 터미널에서 실행한다. OTP가 필요하면 프롬프트에 입력한다.

```bash
pnpm release-it -V
npm view @cp949/react-webcam version dist-tags --json
git ls-remote --tags origin refs/tags/v2.0.0
```

`pnpm release-it -V`는 버전 증가, changelog 생성, 커밋, 태그, 원격 push,
npm publish를 수행한다. `v2.0.0` push는 GitHub Release 워크플로우도 실행한다.
GitHub Actions의 Release 작업과 npm의 `latest: 2.0.0`을 확인한다.

위험: 높음. `pnpm release-it -V`는 공개 배포와 원격 Git 변경을 수행한다.
rollback: npm 배포 전에는 로컬 변경을 검토해 되돌릴 수 있다. 배포 후에는 같은 버전을
덮어쓸 수 없다. 문제가 생기면 소비자 버전을 1.3.0으로 고정하고 수정 버전을 배포한다.

태그·커밋 생성 뒤 npm publish만 실패했다면 `pnpm release-it`을 반복하지 않는다.
해당 릴리스 커밋의 `packages/react-webcam` 디렉터리에서 다음 명령만 다시 실행한다.

```bash
pnpm publish --no-git-checks
```

## 검증 범위

- 패키지 테스트 266개, 데모 테스트 13개, 타입 검사, 빌드, Chrome 75 정적 검사를 통과했다.
- 실제 tarball을 임시 소비자에 설치하고 React 19 마운트, 미디어 제약 전달,
  장치 조회, 트랙 종료와 Chrome 75 대상 번들 생성을 확인했다.
- npm 패키지에 ESM/CJS, 타입 선언, LICENSE, 한국어·영어 README, `llm.txt`가 포함된다.
- 기존 lint 경고 4개와 TypeScript 7.0 실험 API·기존 `use client` 번들 경고가 남아 있다.
- Chromium 83.0.4103.116 컨테이너의 Playwright 스모크 테스트 1개가 통과했다.
  시뮬레이션 카메라의 영상 프레임, 실제 마우스로 스냅샷 버튼 클릭, 스냅샷 이미지
  로드, 언마운트 시 트랙 종료를 검증했다. 제품 코드에 브라우저 폴리필을 주입하지 않았다.
- 소비자 검증 스크립트는 임시 프로젝트에서도 pnpm 12.4.1을 사용한다.
  Chrome 83 스모크는 최신 Playwright의 `checkVisibility` 의존을 피하도록 기본 DOM API로
  준비 상태를 검사한다.
- 2.0.0 배포 전 추가 검증(Chromium 83 컨테이너, `use-webcam.spec.ts` 6개 통과):
  `display: none` video에서 `isFrameReady`와 언마운트 시 트랙 종료,
  `allow` 속성 없는 교차 origin iframe의 `policy-blocked`와 `allow="camera"` 대조군,
  `track-ended` 뒤 `retry()` 복구, `muted` 없는 video 재생.
- Chrome 75 실행, 실제 카메라 하드웨어와 Safari는 검증하지 않았다.
